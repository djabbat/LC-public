## §0g. Reference Coding (XERJ) + внешнее признание CEDAR — 2026-10-22

> Мастер-анализ: `~/Desktop/Services/docs/XERJ_REFERENCE_CODING_ANALYSIS_2026-10-22.md`. **Полезное для LC / MCARA / CEDAR:**
1. **Внешнее (независимое) инженерное признание CEDAR:** человеческий отбор работы «typed StatusTransition + PolicyConfig (JSON graph+policies), +7 тестов, 136 total» в публичный хаб решений — сигнал качества стиля разработки (типизированные конечные автоматы + data-driven политики + аудит-мембрана). Для грантов — аргумент зрелости инженерного продукта.
2. **Ref coding = ускоритель Rust-разработки:** индексировать OSS-крейты рядом с задачей (nalgebra/rand/rayon/tokio/criterion…) и перед написанием нетривиального кода получать `defs`+`body`+`file:line` вместо переизобретения API. Парадигма подтверждена литературой RACG: REDCODER arXiv 2108.11601; EVOR arXiv 2402.12317 (2–4× accuracy на fresh-библиотеках); Repoformer arXiv 2403.10059 (селективный ретривал, −70% latency); repo-level code search arXiv 2502.07067 (+80% MAP/MRR).
3. **«Гейт меморизации»:** ретривал выигрывает на нишевом/своём коде (у LC — уникален), проигрывает на популярных API, которые модель помнит (To Retrieve or Not arXiv 2501.09292). Использовать как средство, не метрику.
4. **Знание-кредит:** числа XERJ (2.7×/6.5×) — самозамер вендора на синтетических библиотеках, не peer-reviewed и не реплицирован; направление/механизм подтверждены литературой, конкретные коэффициенты — нет (мета-анализ слабых мест — в мастер-документе).

3. **Сенолитик-мишени:** структурные карты BCL-2/MDM2–p53 как основа будущего дизайна лигандов.

**Рекомендуемый следующий шаг (малозатратный пилот):** на GPU-сервере (512 ГБ RAM): скачать FoldSeek AFDB50-индекс → прогнать запросы по 5–10 мишеням старения → таблица гомологов (топ по E-value/tM-score) → записать в LC/EVIDENCE.md.
